# 重叠子图层次索引与 OracleCoverage 设计

## 1. 研究问题与第一阶段范围

研究问题：在索引空间和检索预算相同的条件下，允许区域重叠的层次索引，能否提高跨越划分边界的 query 匹配召回率，并减少后续精确子图匹配的搜索量？

第一阶段先实现实例级真值、结构表示和有预算的 OracleCoverage 上限分析。模型训练（包括 BART）、学习式排序和 GPU 评估不属于本阶段。OracleCoverage 用于检验表示本身的能力上限，不等同于训练模型后的实际召回率。

## 2. 对象与数据表示

必须分开保存以下对象：

1. **模式类型**：无标签无向图的同构类型。按图同构规范化后去重，并映射为稳定 token，例如 `<tri>`、`<square>`。
2. **模式实例**：某模式在原图中的一次具体出现，保存原图节点 ID、从规范模式顶点到原图节点的映射、模式类型及发现轮次。不同位置的同构实例不能去重。
3. **层次区域**：由一个或多个实例合并形成的索引节点，保存子节点 ID、原图节点覆盖集合、组合标签及实例来源。原图 `G` 是边集合的唯一来源，区域记录不重复保存边列表。
4. **收缩历史**：每轮收缩前后的节点对应关系、被收缩实例、原图成员和组合标签。不同发现轮次属于不同粒度，不得未经显式展开就放在同一叶层。
5. **残余信息**：未被模式实例覆盖的原图节点和边单独保存，以支持还原与计算边界连接；不为它们创建模式 token 叶子。

Token 序列只标识模式类型。候选组合记录共享的原图节点 ID；需要判断边关系或计算组合标签时，从原图 `G` 查询，不在每条关系记录中复制边信息。

模式表示采用**有限模式词表 + 递归组合规则**。词表只收录经筛选的无标签无向简单图结构类型，且不允许自环；较大的结构优先表示为子模式类型及其节点重叠关系。只有当组合结构达到最低支持频次，或带来明确的索引/压缩收益时，才提升为独立模式 token；稀有组合保留为组合表达，不要求为所有大图结构分配 token。每个类型有稳定的机器 ID，可为常见结构附加 `<tri>`、`<butterfly>`、`<diamond>` 等人类可读别名。词表大小由最大模式规模、支持频次门槛及索引收益门槛控制，不在第一阶段枚举所有可能的图同构类型。

**模型递归组合的基础单元**是有界频繁模式类型在原图 `G` 中的具体出现实例，不是单个原图节点或边。基础模式集合由配置的节点数范围 `[k_min, k_max]`、最低支持频次 `sigma`、预设 query 模式及频繁子图挖掘结果共同确定。词表按同构类型去重，叶子按原图实例保留。实例记录规范模式顶点到原图节点的映射；模式的边结构由模式类型定义，原图 `G` 是实际边关系的唯一来源。收缩后才发现的更大模式作为组合规则或候选父模式，不混入基础叶子集合。

## 3. 精确匹配器接口

精确子图匹配采用现有算法作为数据标注与评估工具，本阶段不研究或改进匹配算法本身。输入为无标签无向 query 和最终原图 `G`；输出为匹配实例及其 query 到原图的节点映射。实现须沿用项目选定匹配器的既有匹配语义，并统一用于数据生成、采样和 OracleCoverage。

OracleCoverage 需要知道匹配枚举是否完整：枚举完成时使用完整实例集；若匹配器受预算限制而提前停止，则将指标标注为估计值并记录状态。除此接口要求外，匹配算法的实现细节不属于本次设计重点。

## 4. 实例合并与有界重叠层次

表示分为两个关联视图，不能把“选作索引的合并”误当成“唯一可能的组合关系”：

1. **索引树**：为了控制区域数量和检索成本，每个实例叶子在索引树中至多有一个父节点。索引树从可行候选中确定性地选一个合并；并列时按稳定 ID 打破平局。这个选择只决定索引布局，不删除或否定其他候选。
2. **候选组合关系图**：保留搜索过程中实际探索且通过约束的候选组合。一个实例或区域可参与多个候选关系，也可对应多个候选父区域，因此该视图是有向无环组合图（若候选含多个子项，则记录为超边），而非树。它提供给后续模型作为可探索的组合证据。

候选关系图只承诺包含算法在指定搜索预算内探索到的候选，不代表穷举了所有数学上可能的组合。未被探索或未进入预算的长尾关系标为“未知/未枚举”，不能作为负例，也不能据此宣称实例无关。模型训练时可使用候选组合证据；实际索引检索仍可使用预算受限的索引树。

把原先单一的 `R` 拆成两个量：

- `tau`：局部重叠相似度门槛，范围 `[0,1]`。两区域 `a,b` 的相似度为 `|V_a ∩ V_b| / min(|V_a|, |V_b|)`；当相似度不低于 `tau` 时，可进入重叠候选。
- `R`：全局重复引用预算，定义为 `sum_a |V_a| / |union_a V_a|`，其中求和覆盖同一层的区域。它限制冗余表示成本，而非局部相似度。

若两区域间存在原图跨边，即使它们节点不相交，也可作为连接候选。候选关系图记录全部已探索且满足条件的候选，不因索引树选择了另一个父节点而丢弃。索引树的候选选择须满足全局 `R` 预算；排序优先最大化新增覆盖节点数与新增索引存储成本之比，重叠/跨边连接作为可行性与次级排序依据。所有计算使用原图节点 ID，不通过从 G 删除实例节点来计算重叠。

叶层由全部满足支持条件的具体模式实例构成，其自身重复引用率是不可消除的基线。显式给出的 `R` 若小于此叶层基线，构建应报错并显示最低可行值；省略 `R` 时自动采用叶层基线作为预算。之后每层的合并仍须满足该预算。每层记录可能配对数、实际探索配对数、候选数及是否触及搜索上限；搜索预算截断时，候选图只表示已探索部分，未枚举部分仍为未知。

每条候选组合关系至少记录子实例/区域 ID、双方原图节点集合（或足以恢复它们的映射）、共享节点 ID、结果覆盖节点集合、组合标签、探索层数和候选状态；不重复保存共享边或连接边列表。模型可从实例节点集合的交集学习重叠关系，组合标签作为监督目标。候选标签语义必须明确：两个三角形共享两个节点时，它们共享一条边，完整并集是含弦的四节点图，但其中包含一个四环；若 `<square>` 表示“组合中可抽取的四环子模式”，该标签成立，若表示“完整并集恰好同构于四环”，则不成立。两个三角形共享一个节点时，组合结果是五节点、六边的蝴蝶结结构，可用 `<butterfly>` 作为组合标签。标签生成阶段可以查询原图边集合，但关系样本不复制这些边。

递归组合规则作为显式语法记录，例如 `<butterfly> ← <tri> ⊕[共享 1 个节点] <tri>`、`<diamond> ← <tri> ⊕[共享 1 条边] <tri>`。若某组合未达到独立 token 的晋升门槛，仍可保留为由子 token、重叠关系和组合层级组成的规则表达。模式 token 表示精确的规范图结构；其人类可读别名只提供拓扑含义，不推断当前无标签图中不存在的领域语义。

`H` 是从叶子向上探索时允许的最大普通合并层数，适用于索引树和候选组合关系图。索引树到达 H 后若仍有多个前沿节点，则创建虚拟 `<bos>` 根汇总它们；BOS 不宣称增加真实原图覆盖。树中每个区域节点保存节点覆盖、父子关系、组合标签和合并原因；候选组合图另存所有已探索关系及其节点重叠证据。

## 5. 合成数据

用固定随机种子生成 10 个互不相同的小型无标签无向 query，包含三角形、四环、三叶星等基础模式及由它们构成的复合 query。第一版将三角形、四环和三叶星作为基础叶子模式；复合 query 保留为查询任务，不自动全部加入叶子词表，以便能测量跨叶子边界的覆盖。通过共享节点、共享边、桥接边三类拼接方式植入 query，每个 query 至少植入 5 次。随后在植入图上随机增加不超过 15 个节点和不超过 15 条无向边，并保证最终 `|V(G)| < 500`。生成器需保存 planted provenance，但最终监督真值必须在扰动后的 G 上重新运行精确匹配得到。

第一阶段重点标注完全位于单个基础实例内和跨实例边界的匹配。若某 query 在最终图中不足 5 个去重实例，数据记录其真实数量，不虚构样本。高组合度 query 的匹配枚举允许配置上限，并按第 3 节记录不完整状态。

## 6. 区域能力上限和评估

给定区域节点大小上限 `m`，定义：

`OracleCoverage(m) = 区域大小不超过 m 且完整包含匹配节点集的真匹配数 / 全部真匹配数`。

同一匹配若被多个区域覆盖只计一次。还需报告候选区域数量、区域大小、为验证候选而检查的原图节点/边规模、构建耗时和精确匹配枚举状态，并按跨边界/非跨边界匹配分层统计。

比较三种索引基线：非重叠区域、允许重叠的层次区域、固定半径邻域区域。对比时使用相同的索引存储预算和候选检索预算；报告各预算点的 OracleCoverage 上界、可行贪心覆盖率及验证工作量。Oracle 上界由忽略区域间覆盖重叠的基数和/存储分数背包松弛共同给出，保证不低估预算下的最优覆盖，但不一定可达到；贪心解是实际可行的下界。两者相等时最优值已确定，否则报告上下界间隙。节点工作量按贪心选中区域的节点数求和；边工作量按每个贪心选中区域在原图中诱导子图的实际边数求和，避免只统计区域结构中保存的模式边而低估验证成本。Oracle 上界是索引能力上限，不代表学习器实际性能。

## 7. 多样实例样本选择与后续训练接口

后续若进入模型阶段，对每个 query 从最终图全部精确匹配中选择 `B=5` 个实例。覆盖多样性按宿主图位置/上下文衡量：对匹配 `g`，定义半径 `r` 邻域 `C_r(g)` 为到匹配节点距离不超过 r 的节点集合；使用确定性的贪心新增加权覆盖选择实例，并在不足 5 个不同匹配时返回实际可用数量。该策略是覆盖导向采样，不代表均匀随机抽样。

训练数据保存完整匹配映射和 query 图结构。未采样的匹配仍是潜在正例，不得作为负例。第一阶段只产出这些可复用数据，不训练 BART，也不把节点并集当作实例级标签。

## 8. 输出文件与记录结构

可复现实验输出至少包括：无标签无向原图与随机种子、query 图集、模式类型词表、模式实例及原图映射、收缩历史、残余节点/无向边、预算受限的索引树、已探索候选组合关系图、最终图上的精确匹配 JSONL，以及按 query/区域上限统计的 OracleCoverage 报告。ID 使用稳定字符串或整数；集合序列化前排序，确保相同种子可比较。

匹配 JSONL 每行至少包含：`graph_id`、`query_id`、`match_id`、`query_to_graph`、`host_nodes`、`host_edges`、`cross_boundary`。索引区域记录至少包含：`region_id`、`parent_id`、`children`、`source_occurrence_ids`、`covered_nodes`、`level`。候选组合关系记录至少包含：`candidate_id`、`child_ids`、`child_node_sets`、`shared_node_ids`、`result_pattern_type`、`covered_nodes`、`level`、`exploration_status`、`selected_for_index`。`host_edges` 只存在于原图及匹配真值中；组合关系不冗余存储边列表。

## 9. 失败与边界处理

无模式实例时返回空词表和空叶层；有多个叶子时 BOS 收拢剩余前沿；仅一个叶子时该叶子可作为根，不强制增加 BOS。违反 `|V(G)| < 500`、负预算、非法 `tau/R/H` 或 query 边集合不合法时应给出清晰错误。匹配枚举受限时保留部分结果并明确标记不完整，不能报告为精确全量指标。

## 10. 非目标

- 不训练或微调 BART，不实现模型节点分类目标。
- 不在第一阶段证明跨图泛化或真实数据集上的研究收益。
- 不把植入实例直接当作扰动后真值。
- 不将未覆盖节点伪装成模式实例叶子；残余节点和边仅作为独立元数据保存。
