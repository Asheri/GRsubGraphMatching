# BART 区域路径生成训练实验设计

## 1. 目标与范围

本实验验证：给定一个无标签无向 query 和一张目标图的层次索引，BART 能否生成有用的区域路径，使精确匹配器能在有限候选区域内找回多个合法匹配实例，并在未见过的图上保持效果。

模型只负责提出索引区域路径；路径解析、区域节点集合读取和最终子图匹配由确定性程序完成。本阶段用合成图做初步跨图泛化实验，不据此声称真实数据集效果或对未见 query 结构的泛化。

## 2. 数据与索引准备

固定同一组 10 个无标签无向 query，独立生成 3 张训练图和 1 张测试图。各图使用不同随机种子，并分别执行模式植入、随机扰动、模式实例发现、索引树构建和精确非诱导匹配枚举。测试图上的实例、匹配、区域路径及索引信息不得进入训练。该划分测量固定 query 集上的跨图泛化，不测量未见 query 结构的泛化。

为保证不增加单点叶子且所有 query 匹配都能映射到索引区域，在每个 planted query 的宿主节点上添加确定性的基础模式覆盖骨架：3 节点 query 补成三角形，4 节点 query 补成三叶星，5 节点 query 补成两个共享一个节点的三角形。原 query 的边全部保留，因此标注和检索采用非诱导匹配。覆盖骨架新增边单独记录，不计入随机扰动的至多 15 条边。额外随机节点保持孤立，随机边只在已有基础模式覆盖节点之间添加；由于 query 均连通，额外随机节点不会参与 query 匹配。精确匹配枚举后还须验证每个匹配的宿主节点集合均被至少一个基础模式实例覆盖，违反时数据准备失败并输出缺失节点。

重新生成索引时将 `tau` 设为 `0.30`，保证单节点重叠的三角形组合可进入候选；组合关系搜索不在 5,000 对处截断，或者在实验元数据中明确保留并报告实际搜索预算及截断状态。保留每张图上全部 query 到最终图的精确匹配映射，并记录枚举是否完整。不同图使用互不复用的宿主节点 ID 命名空间。

每个树节点代表原图中的一个区域，区域覆盖集合为其后代基础实例节点集合的并集。BOS 根仅汇总前沿区域；它不创建新的原图节点，也不作为检索结果。为避免模型总是选择几乎覆盖整张图的根区域，只有非虚拟且至多 12 个节点的区域能作为训练目标和检索候选；没有合格区域的匹配记为未覆盖。对每个精确匹配，监督路径指向覆盖该匹配全部宿主节点的最小合格区域；若多个同尺寸区域满足条件，按稳定的区域 ID 选择。路径编码为从根开始的子节点序号 token 序列，例如 `<child_0>/<child_1>`。树构建及子节点排序必须确定性，以保证路径可复现。

训练输入包含 query 的确定性图结构序列化，以及对应训练图的索引上下文：区域路径、区域组合 token、子区域关系、覆盖节点 ID 和由原图派生的区域结构摘要。每张图按自身索引树解释路径；测试图上下文在推理时提供给模型。目标包含一个或多个匹配映射对应的区域路径。未采样的真匹配不得用作负例。每个 query 在每张图上的匹配实例按现有覆盖贪心策略选取最多 5 个作为监督实例，并保留该图的完整真值集合用于评估。

## 3. 模型与训练

采用小型 BART encoder-decoder，从随机初始化开始训练，避免把自然语言预训练能力误当作结构学习能力。模型配置、随机种子、词表、路径 tokenization、训练步数、学习率、批大小和 checkpoint 均写入运行配置及结果元数据。解码采用确定性 beam search，输出最多 5 条路径；无效路径、重复路径和无法解析的路径均计为无效预测并记录。

使用全部 10 个固定 query 在 3 张训练图上训练，在完全独立的第 4 张图上测试。服务器确认有 3 张 GPU 时，启动三个独立随机种子运行，每个运行使用独立进程及显式设备参数 `--device cuda:0`、`--device cuda:1`、`--device cuda:2` 并行训练；若 GPU 数量与计划不符，停止训练并重新安排。三个运行使用完全相同的图级训练/测试划分，只改变模型随机种子。报告各随机种子的测试结果，以及均值和标准差；不将同一张图中的 query-match 样本拆分到训练集和测试集。

## 4. 推理与指标

推理流程：BART 按分数生成候选区域路径；程序解析并去重路径，丢弃 BOS 和大于 12 节点的区域；最多验证 5 个区域，并在最多 250 个区域节点引用的预算内，用与数据标注相同语义的精确匹配器枚举合法 query 实例；按路径顺序及匹配器稳定顺序去重实例，最多返回 5 个。

所有检索指标以精确枚举的 query 匹配集合为真值。路径无法解析、区域无匹配或重复返回的实例不计为命中。测试集真值不完整时，相关指标必须标记为估计值。

- `Recall@1`：首个合格预测区域是否能返回至少一个属于完整真值集合的实例；若首条路径无效、无法解析或区域内无合法匹配，则记 0。
- `Recall@5`：前 5 个返回实例中命中的不同真匹配数，除以该 query 的真匹配总数。
- `Precision@5`：前 5 个返回位置中命中的不同真匹配数除以 5；若不足 5 个结果，空缺位置按未命中计算。
- `F1@5`：`Precision@5` 与 `Recall@5` 的调和平均；两者均为 0 时记为 0。
- `PathValidity@5`：最多 5 条候选路径中可解析、非虚拟、区域大小不超过 12 且经精确匹配验证至少返回一个 query 匹配的比例。
- 同时报告不同合法结果数、区域节点/边验证工作量、推理耗时，以及匹配枚举完整性。

先对测试图的每个 query 计算指标，再对 10 个 query 取宏平均；最后报告三个随机种子的均值和标准差及各 query 明细。对测试图上完全没有真匹配的 query，Precision/Recall/F1 记为不适用并单独报告，不混入宏平均。

## 5. 基线与结果

使用相同索引和精确验证预算，比较 BART 路径检索与随机区域、按区域大小排序、固定半径邻域检索；同时报告已知真值下的 Oracle 上界。基线和 BART 最终都由同一精确匹配器产生实例，因而指标定义一致。

输出训练配置、每个随机种子的训练日志、checkpoint、测试 query 级预测路径、精确匹配结果、指标 JSON/表格和运行环境信息。指标需同时提供 Recall@1、Recall@5、Precision@5、F1@5、PathValidity@5 及验证成本；单一综合分数不得替代这些原始指标。

## 6. 运行环境与失败处理

训练环境固定 Python、uv、PyTorch、Transformers 及训练所需依赖版本，并提交 lock 文件；服务器使用项目虚拟环境运行。启动前记录 `uv`、Python、CUDA、驱动和 GPU 数量。三个训练进程显式指定各自使用的 GPU。

任何训练阶段错误均按项目全局约定记录到 `training-errors.md`，包括时间、阶段、关键日志、根因、修复和验证方式。运行失败时保留配置、日志及已完成随机种子结果；不得将不完整运行汇总成完整实验结果。

## 7. 成功判据与局限

实验成功运行的判据是：3 个随机种子运行均完成，且在独立测试图上产出可复现的路径、实例级预测和完整指标；质量结论依据各指标与基线对比，不预设 BART 一定优于基线。训练图数量和 query 数量较少，结果只用于决定是否继续扩大数据与模型实验。

## 8. 非目标

- 不改进或替换精确子图匹配算法。
- 不训练节点二分类器或直接生成 query 到宿主图的节点映射。
- 不把小规模合成图实验结果外推为真实数据集效果或普遍的跨图泛化能力，不预设模型优于启发式基线。
- 不把未探索的组合关系作为负样本。
