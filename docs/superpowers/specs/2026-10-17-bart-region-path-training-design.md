# BART 区域路径生成训练实验设计

## 1. 目标与范围

本实验验证：给定一个无标签无向 query，BART 能否从固定大图的层次索引中生成有用的区域路径，使精确匹配器能在有限候选区域内找回多个合法匹配实例。

模型只负责提出索引区域路径；路径解析、区域节点集合读取和最终子图匹配由确定性程序完成。本阶段是单图、合成数据上的可行性实验，不据此声称跨图泛化或真实数据集效果。

## 2. 数据与索引准备

使用现有 10 个 query 和单张合成无标签无向图。重新生成索引时将 `tau` 设为 `0.30`，保证单节点重叠的三角形组合可进入候选；组合关系搜索不在 5,000 对处截断，或者在实验元数据中明确保留并报告实际搜索预算及截断状态。保留全部 query 到最终图的精确非诱导匹配映射，并记录枚举是否完整。

每个树节点代表原图中的一个区域，区域覆盖集合为其后代基础实例节点集合的并集。BOS 根仅汇总前沿区域；它不创建新的原图节点。对每个精确匹配，监督路径指向覆盖该匹配全部宿主节点的最小区域；若多个同尺寸区域满足条件，按稳定的区域 ID 选择。路径编码为从根开始的子节点序号 token 序列，例如 `<child_0>/<child_1>`。树构建及子节点排序必须确定性，以保证路径可复现。

训练样本输入包含 query 的确定性图结构序列化；目标包含一个或多个匹配映射对应的区域路径。未采样的真匹配不得用作负例。每个 query 的匹配实例按现有覆盖贪心策略选取最多 5 个作为监督实例，并保留完整真值集合用于评估。

## 3. 模型与训练

采用小型 BART encoder-decoder，从随机初始化开始训练，避免把自然语言预训练能力误当作结构学习能力。模型配置、随机种子、词表、路径 tokenization、训练步数、学习率、批大小和 checkpoint 均写入运行配置及结果元数据。解码采用确定性 beam search，输出最多 5 条路径；无效路径、重复路径和无法解析的路径均计为无效预测并记录。

使用 query 级 3 折交叉验证，确保同一 query 不同时出现在训练集和测试集。服务器确认有 3 张 GPU 时，每折使用独立进程及显式设备参数 `--device cuda:0`、`--device cuda:1`、`--device cuda:2` 并行运行；若 GPU 数量与计划不符，停止训练并重新安排。报告每折结果及宏平均，不把同一 query 的样本随机拆分到训练集和测试集。

## 4. 推理与指标

推理流程：BART 按分数生成最多 5 条区域路径；程序解析并去重路径；在对应区域内用与数据标注相同语义的精确匹配器枚举合法 query 实例；按路径顺序及匹配器稳定顺序去重实例，最多返回 5 个。

所有检索指标以精确枚举的 query 匹配集合为真值。路径无法解析、区域无匹配或重复返回的实例不计为命中。测试集真值不完整时，相关指标必须标记为估计值。

- `Recall@1`：首个返回的不同合法匹配实例是否命中完整真值集合，除以该 query 的真匹配总数。
- `Recall@5`：前 5 个返回实例中命中的不同真匹配数，除以该 query 的真匹配总数。
- `Precision@5`：前 5 个返回位置中命中的不同真匹配数除以 5；若不足 5 个结果，空缺位置按未命中计算。
- `F1@5`：`Precision@5` 与 `Recall@5` 的调和平均；两者均为 0 时记为 0。
- `PathValidity@5`：前 5 个解码路径中可解析且确实包含至少一个 query 匹配的路径比例。
- 同时报告不同合法结果数、区域节点/边验证工作量、推理耗时，以及匹配枚举完整性。

宏平均先在每个 query 上计算指标，再对 query 取平均，最后报告三折宏平均及每折结果。对完全没有真匹配的 query，Precision/Recall/F1 记为不适用并单独报告，不混入宏平均。

## 5. 基线与结果

使用相同索引和精确验证预算，比较 BART 路径检索与随机区域、按区域大小排序、固定半径邻域检索；同时报告已知真值下的 Oracle 上界。基线和 BART 最终都由同一精确匹配器产生实例，因而指标定义一致。

输出训练配置、每折训练日志、checkpoint、query 级预测路径、精确匹配结果、指标 JSON/表格和运行环境信息。指标需同时提供 Recall@1、Recall@5、Precision@5、F1@5、PathValidity@5 及验证成本；单一综合分数不得替代这些原始指标。

## 6. 运行环境与失败处理

训练环境固定 Python、uv、PyTorch、Transformers 及训练所需依赖版本，并提交 lock 文件；服务器使用项目虚拟环境运行。启动前记录 `uv`、Python、CUDA、驱动和 GPU 数量。训练命令显式指定每个折对应的 GPU。

任何训练阶段错误均按项目全局约定记录到 `training-errors.md`，包括时间、阶段、关键日志、根因、修复和验证方式。运行失败时保留配置、日志及已完成折结果；不得将不完整折汇总成完整实验结果。

## 7. 成功判据与局限

实验成功运行的判据是：三折均完成且产出可复现的路径、实例级预测和完整指标；质量结论依据各指标与基线对比，不预设 BART 一定优于基线。单图十个 query 的规模较小，结果只用于决定是否继续扩大数据与模型实验。

## 8. 非目标

- 不改进或替换精确子图匹配算法。
- 不训练节点二分类器或直接生成 query 到宿主图的节点映射。
- 不宣称跨图泛化、真实数据集有效性或模型普遍优于启发式基线。
- 不把未探索的组合关系作为负样本。
