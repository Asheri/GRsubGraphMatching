# 重叠子图层次索引实现计划

> **面向 AI 代理的工作者：** 本计划按下列任务顺序在当前工作区内执行。工作区没有 Git 仓库，因此不创建 worktree 或提交。遵循用户已确认的设计规格。

**目标：** 构建有界频繁模式实例、递归组合候选图、预算受限索引树和 OracleCoverage 的可运行数据流水线。

**架构：** 复用现有 FLEXIS 模式挖掘与 NetworkX VF2 匹配能力；用模式类型词表、原图实例映射和节点重叠关系表达组合。保留候选组合关系图与用于检索的单父索引树两种视图，并将合成数据、树结构、精确匹配和覆盖率报告导出为 JSON。

**技术栈：** Python 3.12、NetworkX 3.7、现有 FLEXIS 调用封装。

---

## 文件边界

- 创建 `pattern_instances.py`：规范化无标签无向模式类型、枚举模式出现并提供有界基础模式实例。
- 创建 `synthetic_data.py`：构造 10 个 query、植入模式、施加扰动并保留 planted provenance。
- 创建 `overlap_hierarchy.py`：生成候选组合关系图、有限模式词表/递归规则和预算受限索引树。
- 创建 `oracle_coverage.py`：精确匹配结果上的 OracleCoverage、候选区域预算与基线统计。
- 创建 `run_experiment.py`：串联配置、运行流程并写出可复现 JSON 文件。
- 修改 `subgraph_sampling.py`：提供完整精确匹配枚举映射的公开接口，复用现有 VF2 语义。
- 修改 `README.md`：记录参数、数据格式、命令和 FLEXIS 可选依赖。

## 任务 2：合成图与 query 数据

**文件：**
- 创建：`synthetic_data.py`

- [ ] 实现固定种子下的 10 个无标签无向 query；叶子基础模式限制为三角形、四环和三叶星，其他复合 query 用于跨叶子边界评估。
- [ ] 为每个 query 至少植入 5 个实例；组合方式覆盖共享 1 个节点、共享 1 条边和通过桥接边连接，并记录 query 到宿主图的 planted provenance。
- [ ] 随机增加至多 15 个节点和 15 条边，检查最终图小于 500 个节点；最终监督匹配须从扰动后的图重新枚举。
- [ ] 导出原图、query 集和 provenance 的 JSON 记录；节点 ID 和无向边在写出前稳定排序。

## 任务 3：递归候选组合图与索引树

**文件：**
- 创建：`overlap_hierarchy.py`

- [ ] 以基础模式 occurrence 为叶子；每轮只组合同一层的候选区域，候选条件为共享节点相似度达到 `tau` 或原图中存在连接关系。
- [ ] 保留所有预算内探索到的候选组合关系；记录 child IDs、child node sets、shared node IDs、结果模式类型、层级和索引树入选状态，不复制边列表。
- [ ] 两个三角形共享一个节点时标记 `<butterfly>`；共享两个节点时完整并集标记 `<diamond>`，并允许记录其包含 `<square>` 子模式。
- [ ] 对符合最低支持度或索引收益门槛的组合提升为有限词表类型，其余保留为递归规则表达；未探索组合保持未知。
- [ ] 根据全局重复引用预算 `R` 和覆盖增益/新增存储成本比，确定性地选取每个实例至多一个索引父节点；高度 `H` 结束后用虚拟 `<bos>` 汇总前沿。
- [ ] 提供不重叠和固定半径邻域两种基线区域构造。

## 计划约束

本次不实现或训练 BART，不实现新的子图匹配算法，不把未覆盖节点提升为模式叶子，不将未探索组合当作负例。按开发环境约束，本计划不新增或运行测试；完成后如用户要求验证，再执行相应检查。

## 自检

- 规格覆盖：模式类型/实例分离和基础原子见任务 1；精确匹配接口见任务 1；种子图与扰动见任务 2；候选关系图、重叠预算、索引树和 BOS 见任务 3；OracleCoverage、基线及 JSON 输出见任务 4；非目标见计划约束。
- 命名一致：occurrence 字段统一使用 `type_id`、`node_mapping`、`nodes`；候选字段统一使用 `child_ids`、`child_node_sets`、`shared_node_ids`、`result_pattern_type`。
- 范围边界：FLEXIS 可作为候选模式来源，但流程保留可直接使用预设 query 模式的路径；匹配器仅作为既有数据接口。
